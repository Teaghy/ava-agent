# 知识问答的检索前置约束

客服与知识库预设在服务端执行循环中约束检索，不仅依赖提示词。模型在没有成功检索依据时选择 `ask_user`、`final_answer` 或 `answer_ready`，服务端会将该轮执行改为 `knowledge_search`，查询使用当前用户的原始问题，再把真实检索结果交给下一轮决策。

纠正走正常工具链：权限、租户与知识空间隔离、工具审计、工具预算、检索预算、步数预算、取消和超时全部生效。轨迹中的 `agent_decision.routing` 保存纠正原因和模型原始决策，随后有真实 `tool_call`、`rag_search`、`tool_result` 和 `rag_result`，不会伪造一次“检索成功”。不自动重放业务工具。

模型也可能在未检索时直接返回带引用的回答，使决策服务在返回前就因引用无法映射而抛出 `INVALID_CITATION`。当检索前置条件尚未满足时，执行循环会丢弃这条被拒绝的决策，改为同一条正常检索路径；轨迹记录 `routing.rejectedDecision.code`，不保留未验证的答案正文或把猜测的引用改成真实文档。成功检索后（包括空结果）再出现无效引用，仍原样拒绝，不通过重复检索绕过校验。自由聊天与已有业务依据的回答不启用这条恢复路径。

成功的空结果或不相关的候选资料会直接触发服务端固定拒答，不再让模型自行编写“查不到”的结论；失败或超时不视为空结果。若检索失败后模型仍试图直接结束，返回 `KNOWLEDGE_SEARCH_FAILED`，不保存或流出该结论。工具不可用或无权限时返回 `KNOWLEDGE_SEARCH_REQUIRED`。找到文档后的正式回答仍受引用与回答校验约束。

检索成功不等于问题属于知识库。运行层先根据原始用户问题检查召回资料相关性，输出前再检查实际引用；低相关的真实文档不能作为百科回答的依据，模型改写检索词也不能改变这个边界。排序分数与相关性阈值不同，具体门槛、缓存及误拒答边界见 [回答证据策略](../apps/harness/src/plugins/response-policy/README.md)。范围拒答在 Ops 中记录 `routing.reason=scope_reply` 与 `LOW_CONFIDENCE`，不会清空已有会话或把正常拒答记为系统故障。

客服预设允许已成功执行、结果无错误的业务工具提供依据；知识库预设只接受知识依据。自由聊天预设不强制检索。这项保守约束也会让客服、知识预设中的普通澄清请求先检索一次，以避免依赖小模型准确区分澄清和“知识库没有”的结论；每次运行最多自动补一次失败的检索尝试，预算不会因此放宽。

Ops 的“决策步数”表示实际进入的 Agent 决策轮次。同一步可以包含检索、工具、校验和正文等多个事件，事件列表的数字只表示顺序。达到 `MAX_AGENT_STEPS` 后记录最后实际执行的步数，不再额外加一；进入下一轮决策前会保存检查点，以便运行中查询反映当前轮次。
