# response-policy

内置的可替换回答证据策略，提供 `ctx.responsePolicy`，契约复用 `AnswerPolicy`。可选依赖 `embedding`、`telemetry`；严格知识模式需要可用的 Embedding 进行相关性检查，否则保守拒答。

原生 `Config.evidence` 支持 `knowledge-or-tool`（客服默认）、`knowledge`（知识问答）和 `optional`（自由聊天）。最终答案已有检索文档时必须提供引用；客服允许成功的非检索工具结果作为依据，知识问答只接受检索文档，自由聊天允许直接回答。

客服、知识模式的原始问题必须与知识依据相关，不能把任意召回结果或存在的引用 ID 当作回答许可。成功检索后先检查候选资料；没有相关资料时由服务端固定拒答，不再调用模型决策或正文生成。生成前再检查每一条实际引用，防止混入无关来源；模型生成的 `ask_user` 同样检查范围，不能借追问类型输出百科答案。检查始终使用运行的原始 `goal`，不使用模型改写的检索词。

相关性使用当前 Embedding 对原问题和资料正文重新编码、计算余弦相似度，`Config.minimumSimilarity` 默认 `0.5`。排序融合后的 RRF 分数不能用作相关性或置信度。中英文混合问题中的技术名、产品编号以及算式还须出现在资料中，避免仅加上已知产品名就放行库外问题；不维护“数学/Vue”等禁止主题名单，知识库确实包含这些资料时可以回答。同一运行、同一问题与资料集合的判断最多缓存 128 组；模型切换取消旧运行，新运行重新判断。

阈值是保守的相关性门槛，不能证明所有生成文字都被资料蕴含；引用真实性、正文约束和行业校验仍独立执行。不同 Embedding 的分数分布可能不同，应结合实际知识库校准 `minimumSimilarity`；表达模糊或缺少背景时可能需要补充问题。Embedding 失败保留原基础设施错误，不伪装成“知识库没有”。

`scope_reply` 是运行层生成固定拒答时使用的内部校验类型，模型决策 schema 不接受此类型，客户端仍收到 `ask_user`。它只免除对固定拒答本身的知识相关性要求，引用校验和附加行业策略仍运行；附加策略收到兼容的 `ask_user` 类型。

引用真实性和追加行业校验由基础 Guard 强制执行，不能由此策略关闭。Guard 将策略输入克隆为快照，任何修改都不会改写权威状态。

可通过 `providers.responsePolicy` 启动替换，或通过 Ops 的同名槽位管理独立 JS 插件。停用管理 Provider 时恢复应用或预设策略，失败使用现有 Cordis 装配回退。详见 [应用预设文档](../../../../../docs/application-presets.md)。
